# Diff measures from a `base_sha` pinned at launch

[ADR 0023](0023-early-diff-checks-and-provenance-gated-resume.md) made the accounting measurement and its provenance one shared implementation, but every caller still measured against the *local* default branch: `diff_accounting.evaluate` and `change_capture.resolve_base` computed `git merge-base(base_branch, HEAD)`. The Run's worktree, however, is born from the *fetched* `origin/<default>` tip. When local `main` lags origin — the engineer never fast-forwards their checkout — the merge base sits behind already-merged work, so every measurement charges the Run for commits it never made. A acmeweb Run (`35cc170d`) measured 7,146 counted lines against a 5,000 cap, of which only ~2,200 were the ticket's own; 8 inherited PNGs tripped the binary gate. The failure mode is a Run that overflows or blocks on work that was already merged before it started.

This ADR pins one immutable base at launch and diffs from it everywhere.

1. **The pin is the Run's birth HEAD, resolved in its own worktree.** `lime run` resolves full HEAD immediately after `worktree.create` and the `chdir`, before `session.ensure`/setup, and stores it as `runs.base_sha` (and in the identity card). It is normally the `ticket:` commit; for a pre-existing identical ticket it is the unchanged birth HEAD. No trailer search, no branch-tip recomputation, no extra commit. `--resume` hydrates the pin from the stored row, never from current HEAD, and an incoming replacement or a legacy NULL can never overwrite or backfill it.

2. **Every diff consumer reads the pin, not a branch name.** `git_helper.resolve_diff_base` returns the validated pin for a pinned Run (the pin itself is the comparison commit, never a recomputed merge base) and keeps `merge-base(requested, HEAD)` for a legacy Run. `diff_accounting.evaluate`, `change_capture.resolve_base`, `_review_context`, verification provenance, `_verify_reusable`, and `_pr_body`'s stat all take the pin. `base_branch` survives only as the PR target name handed to `gh pr create`; it is no longer the diff identity anywhere.

3. **An invalid pin is terminal, not an inspection error.** `git_helper.validate_run_base` confirms the pin resolves, is an ancestor of HEAD (`merge-base --is-ancestor` by exit status, not a merge-base result), and that no merge commit was introduced between pin and HEAD. HEAD == pin and linear commits past it pass; merges already in history at/before the pin pass. On any violation it raises `InvalidRunBase`, which propagates through every phase guard, through `_verify_reusable` (never downgraded to a cache miss), and out to the `feature.run` boundary, which traces an `invalid_run_base` error, prints the loud "branch rebased/merged past its base — start a fresh Run" message, and closes the Run `fail` with worktree, branch, plan and content preserved. The guard runs before replay, before any quality command, and before the push, so a bad pin causes no network side effect. `push_pr` validates and builds the PR body before pushing.

4. **Legacy Runs keep today's behavior; the schema migrates in place.** `Tracer._migrate` adds the nullable `base_sha` column to databases created by older builds, idempotently, without backfilling any row. A Run recorded without a pin stays NULL and diffs from its branch exactly as before; a pre-column database resumes with legacy behavior. `ACCOUNTING_VERSION` bumps to 3 so an older measurement is not compared against a pinned one.

We considered,

- **Fast-forward local `main` before measuring.** Rejected: it mutates the engineer's checkout, is racy against concurrent Runs, and still leaves the measurement dependent on a moving ref.
- **Re-derive the base from the ticket commit's trailer after a rebase.** Rejected: a rebase rewrites the commit the Run was born from; reconstructing a base from a trailer would silently measure against history the Run never had, which is exactly the mis-measurement this closes.
- **Fall back to `HEAD`/`HEAD~1` when the pin is unresolvable.** Rejected: a fabricated base would let a Run report success against a diff that is not the ticket's; an invalid pin must fail loud.
- **Treat `InvalidRunBase` as an ordinary inspection error.** Rejected: folding it into the existing "returned as data, never raised" contract would let a phase cache-reuse or retry past it and mis-measure.

Trade-offs accepted: a Run whose branch is rebased or merged past its base is now terminal — the work is preserved but must be restarted as a fresh Run, and the pin is never re-derived or backfilled. The design map's `chore: carry <NN> inputs` commit, re-deriving the base by trailer, backfilling old runs, fast-forwarding the engineer's checkout, and any pre-push accounting pass are out of scope.
