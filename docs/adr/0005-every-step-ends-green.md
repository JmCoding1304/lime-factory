# Every step must end green — no separate failing-test step

Spec asset `10-phase-library-and-chains.md:55` ordered a failing regression test *before* the fix in the bug-fix chain. That step was red, but `verify` gates every step on the full suite (`uv run pytest -q`), so the red step burned every build retry and killed the Run (runs `cf94034b`, `a60391c1`; ticket 65). We considered leaving the spec as-is and adding a plan-shape gate to detect and reject a red-first step in code. We rejected that because the fence would live in code the engineer never reads, and the prompt (which every planner reads every time) is the right place for a first-principles rule. So the planner prompt now says "a 'write failing tests' step is forbidden" and the builder prompt says "never report success while a test you added or touched fails." The cost is losing the TDD-style independent proof that the test catches the bug before the fix exists; the gain is a run that never wastes attempts on a step that cannot pass.
