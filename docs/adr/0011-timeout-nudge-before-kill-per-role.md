# Timeout nudge before kill, per-role wall-clock ceiling

The old `AgentRequest.timeout_s` was 1800 s for every role, reset on each send (JSON-fix retries, gate corrections, stream retries), so it never bounded a Phase's wall clock. On expiry the agent was killed silently — losing all work mid-generation after 48 turns in observed runs. We replaced silent kill with a nudge-under-timer: when the ceiling hits, the Spine sends one prompt ("time is up, submit partial with a handoff") under a short 300 s timer, accepts the partial envelope, and continues via the §9 continuation — same shape as the Budget-stop nudge.

We considered three options:

1. **Silent kill, raise ceiling** — keep the old behaviour but set timeout_s per-role and make it a per-Session cap (i.e. retries don't reset it). Rejected: the real problem in lost Phase runs (2163 s of work gone) is the kill, not the ceiling value. A raised ceiling just postpones the same data loss.
2. **Stall-watch kill-and-retry** — use the existing `StallWatch` (already emits `phase_stalled`) to kill on no-trace-event after N minutes and start a fresh session. Rejected as out-of-scope: false positives on multi-minute thinking gaps, and stalled streams are already covered by pi's 5-minute idle timeout plus tickets 76/81.
3. **Nudge then kill via continuation** — chosen: when the ceiling hits, stop the process's next model call (the Guard's stop effect already exists) and send one nudge into the *same* session under NUDGE_TIMEOUT_S (300 s). If the agent submits a partial envelope, the §9 continuation fires with a fresh clock. If the nudge window also expires, a `timeout_kill` event fires and the phase fails with a code-only handoff. The ceiling is a per-Session bound: every send in the session draws from the one deadline armed at its start, so retries (stream retries, JSON-fix corrections) never extend it.

Key trade-offs accepted: the nudge costs up to 300 s of wall clock and some tokens per Phase that hits the ceiling; a Phase that hits the ceiling twice (first session + continuation) exhausts the §9 continuation and fails, spending two nudge windows. We considered this better than silent data loss, which loses the whole Phase's work. Also accepted: `timeout` status is removed from `transient_error()`, so pi stream timeouts (a separate concern: the 5-minute idle timeout in pi's SSE stream) are no longer retried as timeouts — they surface as `error` with the provider's own reason text, which is still transient and still retried.
