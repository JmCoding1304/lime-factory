# Factory code lives once, as the installed `lime` tool

A factory can copy its Python into every project so each chain can be forked and edited in place. We considered that for limefactory and rejected it: the factory will be improved continuously and pointed at several projects, and no project is expected to need its own chain *code* (only its own config, trust file and prompt overrides). Copying would mean N drifting copies, re-stamping on every fix, and factory code sitting inside target repos where scouts and builders would read or edit it. So the Spine, chains, default prompts, skill and templates ship once in the `limefactory` package installed as `lime`; a project holds only `.lime/` (state, no code) and `.claude/skills/lime/`. The Orchestrator still drives Runs from a shell exactly as a copied-in factory would (`lime run …` instead of running a script from the project); `lime run --show` restores the "read the chain" discoverability that copying gives.
