# Measured diff-cap overflow — stop, preserve, report `needs_rescope`

Status: superseded by [ADR 0060](0060-diff-size-is-measured-never-a-stop.md) — a measured overflow no longer stops the Chain.

[ADR 0017](0017-diff-gate-before-agent-review.md) made the diff gate a hard ceiling and [ADR 0018](0018-uncounted-paths-ship-without-counting.md) gave the builder one legitimate answer to it: report a required large file and let the engineer grant an `commit.uncounted` exemption. Everything else about an oversized diff was still routed back into the ordinary retry loops — the builder was re-prompted to shrink the diff, revised, re-verified, and after `MAX_BUILD_ATTEMPTS`/`MAX_REVISE_ATTEMPTS` the Step failed generically. In practice an ERP incident measured 2,217 and 2,994 added lines against a 2,000 cap, and the retries spent themselves trying to compress work that the ticket actually required. The gate's remediation text still pointed the builder at `commit.uncounted`; nothing stopped it from instead deleting content, `.gitignore`-ing it, or churning until the budget ran out.

This ADR changes only *what happens the instant the cap is measured to be exceeded*. The cap itself, the binary rule, the accounting and the exemption semantics are unchanged.

1. **Overflow is a measurement, not a failure text.** When `verify`'s accounting succeeds and `counted_total > max_added_lines`, it records a `DiffCapOverflow` snapshot on the `VerifyOutput` envelope: the requested base, the full HEAD and merge-base SHAs, the effective `exclude`/`uncounted` patterns and cap, the accounting policy, counted/uncounted/eligible totals, the per-file uncounted list, and the top counted contributors. `diff_cap_overflow is not None` — never a parse of the failure string — is the discriminator, so ordinary quality, binary and inspection-error failures leave the field `None` and keep their existing retry behavior. A snapshot is only minted after accounting succeeded, so an inspection error cannot manufacture an overflow from half-initialized counters.

2. **Both verify call sites stop the Chain on the first snapshot.** `feature.run` checks after the build-phase verify and after the post-revise verify. A hit returns immediately through `_stop_for_diff_cap_overflow`: no further builder, reviser or reviewer, no layout capture, no commit, no documenter, no ticket deletion, no push, no re-plan invalidation, no worktree teardown. The plan, sessions, ticket, branch, index and worktree content are left exactly as they stood.

3. **One deterministic handoff, one preserved outcome.** The stop writes `context_handoff/needs_rescope.json` — the overflow snapshot, the recorded `BuildOutput` reports for the Run's build/revise phases, the outstanding ask/`Done means` checklist with the verify failures and last review, and the existing handoff artifacts — then closes the Run as `needs_rescope`. An ordinary resume is refused, and `lime run --resume` and `session.ensure` both refuse it before any config validation, port check, process row or signal handler, pointing the engineer at the handoff. `needs_rescope` was terminal here; [ADR 0021](0021-event-bound-recovery-of-a-preserved-overflow.md) later added the one explicit, engineer-approved recovery path back to `running`.

We considered,

- **Keep retrying and teach the builder to shrink harder.** Rejected: the recorded incidents show the retries spend the Run's budget failing to compress required content, and the only escapes they leave are exactly the ones ADR 0018 forbids — delete, hide, or over-exclude.
- **Keep the generic `fail` status and add a flag.** Rejected: a preserved, non-resumable Run is a different outcome from a failed Run, and `resume_blocked` plus the CLI must distinguish it ahead of every phase-count and invalidation shortcut.
- **Auto-split the ticket or trim the diff to fit.** Rejected: both destroy required content or work the engineer has not reviewed; splitting is an engineer decision made from the handoff, not a fallback the Spine takes.

Trade-offs accepted: an oversized diff can no longer be retried, so a Run that is genuinely one revise away from fitting the cap still stops and waits for a rescope — the cost of preserving the work intact. Controlled recovery of the preserved worktree is out of scope here and belongs to [ADR 0021](0021-event-bound-recovery-of-a-preserved-overflow.md).
