# Inline `$ref`/`$defs` from role submit schemas before writing to disk

OpenRouter translates a tool's JSON Schema `parameters` into each provider's native function-declaration format before sending it to the model. For Gemini that translation resolves local `$ref` references unreliably: `google/gemini-3.8-flash` sent an array of strings for `findings` (typed as `{$ref: "#/$defs/ReviewFinding"}`) 6 times out of 9 submissions post-ticket-74, and pi rejected every one with "findings.N: must be object". The same model submitted valid payloads 4/4 when the schema was inlined by hand. The `$ref`-based schema worked for every other model tested (glm-5.3-flash, grok-4.6, muse-spark-1.3). We chose to inline every `$ref` into its `$defs` entry — and drop `$defs` — before writing `submit_schema.json` to disk, rather than handle the problem later in `submit.ts` (that file is the pi-coding-agent extension and has no access to the `$defs` map once `parameters` is set, and a `prepareArguments` shim that JSON-parses strings would be a fragile heuristic that only works after the damage is done). The inlined schema is slightly larger (duplicated object definitions) and will become dead code if OpenRouter fixes the Gemini translation, but the correctness guarantee for Gemini is worth the one-time denormalisation cost.
