# Invalidate successful phases after build-attempt exhaustion

A Run whose step exhausts its build/verify attempts dies with a run-level `not_accepted` error, but every phase still reads `status='success'` — `lime run --resume` would replay the whole chain from cache and do zero work. We considered three responses: (1) redesign how `Run.phase()` derives success — the ticket explicitly ruled that out; (2) flip the plan/build/verify rows from `'success'` to `'fail'` — `PHASE_TRANSITIONS` deliberately forbids it because phase status is append-only, and breaking that invariant would undermine the trace's reliability; (3) leave the status alone and record a `phase_invalidated` log event that `replay_map()` excludes — the answer we built. The trade-off is a new event type for a narrow case instead of a clean status change, but it keeps the trace contract intact and respects the transition rules written for Foundation.
