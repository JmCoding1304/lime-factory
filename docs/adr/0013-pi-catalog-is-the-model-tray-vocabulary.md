# pi's own catalog is the dashboard's model vocabulary, not OpenRouter's public list

The profiles page offered models from `https://openrouter.ai/api/v1/models`, so every id it produced was `openrouter/<id>` — metered API usage. The providers pi holds an account with (`openai-codex` on the ChatGPT plan, `anthropic`, `xai`) were unreachable from the UI even when authenticated, and the one list that could name them, `~/.pi/agent/models-store.json`, was already read by Python for the capability preflight and the thinking-support table. We chose to make that store the catalog: `lime models` prints it as `{source, models}` and the dashboard shells out for it, exactly as ADR 0012 has the client learn thinking levels from the server. The offered set is now identical to the set `lime check` accepts, so the tray can no longer name a model a Run would refuse, and prices come from pi's cost table (USD per million tokens) instead of OpenRouter's per-token strings. The trade-off is that a model OpenRouter has just added is invisible until pi refreshes its store — but such a model is unrunnable anyway — and the catalog now costs a subprocess per page load instead of a cached HTTP fetch, which buys the removal of the 1 h cache: a provider authenticated mid-session appears on the next load. Ordering carries the same idea: direct providers sort above the OpenRouter pool, the way the claude_code aliases sort above both.
